# 执行步数设置

默认不设置步数上限，任务持续运行到完成、错误或取消。一步指一次 Agent Loop 的模型调用；
同一步可以执行多个工具，工具重试不单独计为一步。

## TUI 和 CLI

```bash
kama-tui
kama-tui --max-steps 50
kama-tui --resume SESSION_ID --max-steps 50
kama chat --max-steps 50
kama run --goal "分析项目" --max-steps 50
```

`--max-steps N` 接受非负整数，`0` 明确表示不限。负数、浮点数和布尔字符串会在启动时被拒绝。
聊天每条消息启动新的运行并重新计步；参数对当前客户端发出的每轮消息生效，切换或恢复会话也一样。
参数不保存到会话元数据，重新启动客户端时应重新指定。

到达上限且仍需继续时，运行以 `exceeded_max_steps` 结束；如果模型恰好在最后一步完成，仍返回成功。
取消、模型错误、工具权限与工具超时等已有机制继续有效。

## Core 配置

可以继续通过 Core 的配置文件设置默认上限：

```toml
[agent]
max_steps = 50
```

或在启动 Core 的环境中设置 `KAMA_MAX_STEPS=50`。这两种配置中的 `0` 都表示不限。
不设置时默认不限；已有正整数配置仍生效，不会被自动删除或修改。

优先级是：**当前请求／客户端命令行参数 → Core 的现有配置优先级 → 默认不限**。
例如 Core 设置 50，客户端使用 `--max-steps 0`，该客户端发出的运行就不限步数。
没有传参数的客户端仍使用 Core 设置的 50。客户端不会修改 Core 的共享配置。

## IPC 和子 Agent

`agent.run` 与 `session.send_message` 均接受可选字段 `max_steps`：

| 值 | 行为 |
|---|---|
| 省略或 `null` | 使用 Core 配置 |
| `0` | 本轮不限步数 |
| 正整数 | 本轮最多执行相应步数 |

JSON 布尔值、字符串、浮点数和负数均为无效参数。该字段不会改变其他客户端或下一轮请求的默认值。

新建子 Agent 继承父运行实际使用的上限，包括无限模式。父子分别计步，不共享一个累计额度。
已有子 Agent 唤醒时保留创建时的上限，每次运行重新计步；之后父运行改变上限不会追溯修改已有子 Agent。
